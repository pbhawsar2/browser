================================================================================
0. EXECUTIVE SUMMARY
================================================================================

The modular separation is generally sound: HAL owns Linux hardware (zero UI/CEF coupling), policy is pure deterministic state machines, shield/vault/webapp are behind interfaces, engine owns CEF hooks, and app owns the frameless WebUI chrome + tab lifecycle. The shield uses Brave's adblock-rust (not a homemade matcher), the vault uses AES-256-GCM with 0600 keys and atomic writes, and the UI invariants (44px bezel, 38px tab bar, 1.05 zoom) are present.

However, the largest problems are concentrated in:
  1. LIFETIME/OWNERSHIP of async work (detached threads + raw `this` + `base::Unretained`) — use-after-free on quit.
  2. SHUTDOWN / SESSION state machine — session can be overwritten with empty tabs; close can leave a chromeless stuck window.
  3. VAULT origin validation — accepts javascript:/data: schemes (confirmed by Debug test failure hidden in Release).
  4. PERFORMANCE — HUD rebuilds all DOM lists every 2s on the UI thread; download progress pushes full chrome+HUD state; telemetry does filesystem I/O on UI thread; listInstalled() scans the filesystem every HUD tick.
  5. TEST INFRASTRUCTURE — Release builds compile out assertions (DNDEBUG), making 6/6 green meaningless; a Debug run exposes a real vault failure.

Severity key: HIGH = security/data-loss/stability issue that should be fixed before production; MEDIUM = functional/privacy/performance/portability defect with realistic user impact; LOW = hardening/cleanup/doc issue.

1. BUILD / TEST STATUS
================================================================================

- Build: PASS (C++20, -O3 -march=native -Wall -Wextra, zero warnings).
- Unit tests: 6/6 suites pass in Release (explorer_hal, explorer_policy, explorer_shield, explorer_vault, explorer_webapp, explorer_app_stores).
- CRITICAL: Release uses -DNDEBUG; all plain assert() calls are compiled out. The green result is misleading. A Debug build exposes explorer_vault_tests aborting at test_vault.cpp:24 (javascript: origin accepted).
- Rust shield (adblock-rust 0.13): builds staticlib; not covered by ctest.
- No integration/UI tests for BrowserWindow or CEF lifecycle paths.
- No sanitizer (ASan/UBSan/TSan) configuration.

- No -fstack-protector-strong, -D_FORTIFY_SOURCE=2, PIE, RELRO, or -Werror.

2. HIGH-SEVERITY FINDINGS
================================================================================

[H1] Use-after-free: detached threads and posted tasks capture raw `this` / `base::Unretained(this)`
  Files:
    app/src/browser_window.cpp (onTelemetryTick, syncSystemPower, constructor CefPostDelayedTask,
                                onFilterUpdateFinished, onWebAppInstallFinished)
    shield/src/content_shield.cpp (updateFilterListsAsync)
    hal/src/power_governor.cpp (setPerformanceHoldAsync)
    hal/src/display_refresh.cpp (setEdpRefreshRateAsync)
  Detail:
    - BrowserWindow posts CefPostDelayedTask with base::Unretained(this) for onTelemetryTick (rescheduled
      every 2s) and syncSystemPower. These tasks can fire after the window is destroyed.
    - onFilterUpdateFinished / onWebAppInstallFinished check alive_ then post Unretained(this) — race
      between check and task execution.
    - updateFilterListsAsync detaches a thread capturing `this`; the destructor frees handle_. Three curl
      downloads can run ~20s each after the user quits -> UAF on freed shield state.
    - setPerformanceHoldAsync detaches acquire/release threads capturing `this`; shutdown() joins only
      the watcher thread, not these workers.
    - ~BrowserWindow() detaches clients but does NOT call power_gov->shutdown() or display_ctrl->shutdown();
      those are only called from handleWindowDestroyed(). If destroyed via another path, watcher callbacks
      still capture a dead `this`.
  Impact: Use-after-free / crash on quit, especially during filter update or webapp install. Undefined
  behavior, not just a leak.
  Rec: Introduce a refcounted lifetime token (shared_ptr<Lifetime>) captured by every async task; check it
  on the UI thread before touching BrowserWindow. Own all workers in a small executor/thread pool with
  cancel()/shutdown() and join. Do not detach threads that touch object state. Make shutdown() idempotent
  and call it from the destructor too. Use CefPostTask with a refcounted helper rather than base::Unretained.

[H2] Zombie processes from fire-and-forget fork()
  Files:
    app/src/browser_window.cpp (spawnDetachedXdgOpen)
    webapp/src/webapp_installer.cpp (launch)
  Detail:
    - spawnDetachedXdgOpen: fork() + execlp() without waitpid(). Every "Open file/folder" leaks a zombie
      until reaped; accumulates over a long session.
    - LinuxWebAppInstaller::launch: fork() + execl() without waitpid(); the child is never reaped.
  Rec: waitpid() in a detached thread or set SIGCHLD handling. Better: use posix_spawn()/posix_spawnp().

[H3] Vault origin validation accepts non-URL schemes — Debug test fails, Release hides it
  File: vault/src/password_vault.cpp (normalizeOrigin); vault/tests/test_vault.cpp:24
  Detail:
    - normalizeOrigin defaults scheme to "https" whenever input lacks "://".
    - "javascript:alert(1)" -> "https://javascript:alert(1)" -> saveOrUpdate succeeds.
    - "data:text/html,..." -> "https://data:text" accepted.
    - Comment says non-web schemes are rejected, but implementation only rejects when "://" is present.
    - Debug build aborts at line 24; Release compiles out the assert so CI reports green.
  Impact: Vault origin key is not guaranteed to be a real web origin. Future callers trusting normalizeOrigin
  (autofill, credential UI) can be confused by invalid origins. Security contract violated.
  Rec: Use a real URL parser (CEF GURL or a small strict parser). Require valid http/https scheme and
  non-empty host. Reject any scheme not exactly http/https even when "://" is absent. Canonicalize host,
  drop default ports, reject userinfo/invalid ports/control chars. Add tests for javascript:, data:,
  mailto:, file:, chrome:, invalid ports, Unicode hosts.

[H4] Normal shutdown can overwrite saved session with an empty tab list
  Files: app/src/browser_window.cpp (handleCanClose, handleWindowDestroyed, flushSessionNow, onTabClosed)
  Detail:
    - handleCanClose() sets closing_=true, calls flushSessionNow(), then TryCloseBrowser() on every tab.
    - As CEF closes each tab, OnBeforeClose -> onTabClosed() erases the tab from tabs_.
    - handleWindowDestroyed() unconditionally calls flushSessionNow() again; if tabs already erased, it
      writes an empty URL list.
    - Last-tab path: closeTab() calls window_->Close() without removing the tab, then the same sequence runs.
  Impact: Session restore silently loses the user's tabs on normal exit. Depends on CEF close ordering —
  intermittent and hard to reproduce.
  Rec: Save the session once at the start of close and do not save again from handleWindowDestroyed (or
  guard with if (!closing_)). Better: snapshot session data into a local struct in handleCanClose and write
  that snapshot independent of tab teardown. Add integration test: close window with N tabs, verify session
  JSON still has N URLs.

[H5] Close state machine can leave a chromeless, stuck window; is re-entrant
  Files: app/src/browser_window.cpp (handleCanClose, handleWindowDestroyed, onTabDoClose, checkFinishShutdown)
  Detail:
    - handleCanClose() destroys HUD overlay and chrome view BEFORE knowing whether all tabs will close.
    - If a tab's beforeunload cancels, TryCloseBrowser() returns false, handleCanClose() returns false, but
      closing_ is never reset.
    - Once closing_ is true: closeTab() returns immediately (user cannot close remaining tabs); onTabDoClose()
      returns false for every tab.
    - handleCanClose() iterates tabs_ and retiring_tabs_ while calling TryCloseBrowser(); if CEF delivers
      OnBeforeClose synchronously, onTabClosed() can erase the current element and invalidate iteration.
  Impact: A page can cancel window close and leave the browser in a broken UI state (no chrome/HUD, tabs
  uncloseable). Realistic user flow (site with unload confirmation).
  Rec: Do not destroy chrome/HUD until every tab confirms close. Reset closing_ when close is cancelled.
  Distinguish "window close in progress" from "tab close in progress" in onTabDoClose. Copy tab IDs into a
  local vector before TryCloseBrowser so callback-driven erasure cannot invalidate iteration. Add a
  timeout/fallback for OnBeforeClose and a test with a beforeunload handler.

[H6] fork() + non-async-signal-safe child code in a multithreaded CEF process
  Files:
    app/src/browser_window.cpp (spawnDetachedXdgOpen: execlp)
    webapp/src/webapp_installer.cpp (runProcessNoShell: std::vector in child + execvp; launch: std::string +
                                     execl)
    shield/src/content_shield.cpp (updateFilterListsAsync: fork + execlp)
  Detail: After fork() in a multithreaded process, POSIX guarantees only async-signal-safe functions in the
  child before exec. runProcessNoShell builds std::vector<char*> (heap allocation) then execvp (PATH search,
  possible allocation). launch builds std::string in the child then execl(). If another thread holds the
  malloc/stdio lock at fork, the child can deadlock before exec; parent waits forever in waitpid().
  Rec: Use posix_spawn()/posix_spawnp() for all helper processes. If fork must be used, pre-build argv/envp
  before fork and use execv()/execve() with absolute paths; use only async-signal-safe calls in the child.
  Reap children (or double-fork) and handle SIGCHLD.

[H7] Downloads auto-accepted with no user confirmation; Safe Browsing disabled
  Files: engine/src/cef_client.cpp (OnBeforeDownload); engine-builder/args.gn (safe_browsing_mode = 0);
         app/src/browser_window.cpp (dl_open)
  Detail:
    - OnBeforeDownload() immediately calls callback->Continue(dest, false) for every download. No prompt,
      no content-type/size check, no user gesture requirement.
    - Custom engine build sets safe_browsing_mode = 0, so Chromium download protection is unavailable.
    - dl_open opens any completed download path with xdg-open; an executable or .desktop file can be
      launched with one click from the HUD.
  Impact: Drive-by download to ~/Downloads; user social-engineered into opening an executable. Meaningful
  security regression vs mainstream browsers.
  Rec: Ask the user before starting a download (show source URL, filename, size, type). Reject/warn on
  executable MIME types. Enable Safe Browsing or implement an allowlist/warning. Keep "Open File" behind
  explicit confirmation and validate path (inode/hash) before opening.

[H8] PPD performance-hold can leak duplicate holds / lose holds
  File: hal/src/power_governor.cpp (setPerformanceHoldAsync)
  Detail:
    - setPerformanceHoldAsync(true) checks ppd_cookie_.has_value() under the mutex, but the cookie is only
      stored AFTER the asynchronous holdPpdProfileSync() returns.
    - Two rapid true() calls both see empty cookie and both acquire a hold. The second completion overwrites
      ppd_cookie_; the first cookie is lost and never released.
    - shutdown() releases only the single stored cookie.
    - Release and acquire threads are both detached; final PPD state depends on which D-Bus call completes
      last, not on requested state.
  Impact: CPU can remain pinned in performance profile after UI says battery/zero-fan, or requested hold can
  be lost. Repeated toggles accumulate holds.
  Rec: Serialize hold/release through one worker + desired-state state machine. Track a set of outstanding
  cookies (or acquire only when no request in flight). Join/cancel worker in shutdown; release every cookie.

[H9] Local CEF installer reuses world-writable /tmp path; no integrity verification
  Files: install-cef.sh; update.sh
  Detail:
    - If /tmp/explorer-v2-poc/cef/Release and FindCEF.cmake exist, install-cef.sh copies them into
      ~/.local/share/explorer-cef and links against that libcef.so. /tmp is world-writable; another user can
      plant a malicious libcef.so.
    - Normal download uses curl -fL with no checksum or signature. update.sh downloads/extracts a CEF
      archive with no verification.
  Impact: Local privilege escalation (code execution in browser process) or supply-chain compromise if the
  CDN is compromised.
  Rec: Remove the /tmp reuse path entirely or require explicit opt-in + checksum/signature. Pin SHA-256
  checksums for the CEF archive and verify before extraction. Prefer signed package/repository or a
  user-owned cache dir (0700). Validate extracted tree (libcef.so, chrome-sandbox, resources).

[H10] Widevine not actually registered with CEF
  Files: engine/src/cef_flags.cpp; README.md; engine-builder/args.gn
  Detail:
    - Code only appends the enable-widevine switch when /opt/google/chrome/WidevineCdm/manifest.json exists.
    - CEF requires CefRegisterWidevineCdm() with CDM path/version; a command-line switch alone does not load
      a CDM. Hardcoded path only covers Google Chrome on some distros.
    - README claims Netflix/Prime/Hotstar DRM parity.
  Impact: DRM streaming fails even when a Widevine CDM is installed. Feature claim is misleading.
  Rec: Call CefRegisterWidevineCdm() after CEF init with a discovered CDM path/version. Search common
  locations (/opt/google/chrome/WidevineCdm, /usr/lib64/chromium/WidevineCdm, /usr/lib/chromium/WidevineCdm,
  user data dirs). If no CDM found, remove or qualify the DRM claim.

3. MEDIUM-SEVERITY FINDINGS
================================================================================

[M1] Adblock resource-type mapping misses media, fonts, objects, workers, ping
  Files: engine/src/cef_client.cpp (mapCefResourceType); shield/include/explorer/shield/content_shield.hpp;
         shield/src/content_shield.cpp (resourceKindToBraveType)
  Detail: ResourceKind has only MainFrame, SubFrame, Script, Image, Stylesheet, XhrOrFetch, Other.
  RT_MEDIA, RT_FONT_RESOURCE, RT_OBJECT, RT_WORKER, RT_SHARED_WORKER, RT_PREFETCH, RT_FAVICON,
  RT_PLUGIN_RESOURCE all become Other. RT_PING and RT_CSP_REPORT map to xmlhttprequest, so $ping/$csp rules
  do not match their real types.
  Rec: Extend ResourceKind and mapping to the full CEF resource type set. Pass "ping", "media", "font",
  "object", "websocket", "worker" to adblock-rust. Add tests.

[M2] "Secure origin" checks use prefix matching, not host equality
  Files: app/src/browser_window.cpp (vault_fill, lines 959-965); app/src/main.cpp (ContentPageBridgeHandler,
         lines 116-118)
  Detail: live_origin.rfind("http://localhost", 0) == 0 accepts "http://localhost.evil.com".
  rfind("http://127.0.0.1", 0) accepts "http://127.0.0.1.evil.com". Same prefix test on frame URL for login
  capture.
  Rec: Parse the host and require exactly "localhost" or a loopback IP literal, or require https://. Do not
  use string prefixes for origin/security decisions. Reuse the same strict origin parser for vault save,
  vault fill, and login capture.

[M3] Vault key creation and persistence not safe against concurrent instances
  File: vault/src/password_vault.cpp (ensureKey, persistToDisk)
  Detail: Two processes starting with same profile and no key both generate a key; second write replaces
  first. First process then encrypts vault.enc with a key no longer on disk. If vault.key exists but is
  short/corrupt, ensureKey() silently rekeys and orphans all credentials. persistToDisk() has no interprocess
  lock; two instances overwrite each other (last writer wins). Directory not fsynced after rename.
  Rec: Create key with O_CREAT|O_EXCL and never unlink an existing key path. If key exists but unreadable,
  fail closed and preserve it for recovery. Use flock around key creation and vault writes. fsync directory
  after rename; keep backup of previous vault. Consider single-instance lock for profile.

[M4] --profile does not isolate the vault or filter lists
  Files: app/src/main.cpp
  Detail: Session/prefs use cfg_.profile_dir, but services.vault is constructed with defaultProfileDir() and
  shield filters use defaultProfileDir()/filters. --profile=/tmp/foo changes session/prefs/CEF cache but
  leaves credentials and filter state in default profile.
  Rec: Pass launch_cfg.profile_dir to vault and shield (or profile_dir/security subdir). Decide whether
  webapps share or isolate the vault; document it.

[M5] HUD updates rebuild all lists every 2s; filesystem I/O on UI thread (PERFORMANCE — see section 6)
  Files: app/src/browser_window.cpp (pushHudState, onTelemetryTick); chrome_ui.hpp (__updateHud)
  Detail: onTelemetryTick every 2s calls pushHudState which serializes every credential, download, webapp
  and executes a large JS payload. __updateHud clears innerHTML and recreates every DOM node each update.
  listInstalled() scans ~/.local/share/applications and reads each desktop file on the UI thread every HUD
  update.
  Impact: Focus/scroll position lost every 2s; GC churn and disk I/O cause visible jank with many
  credentials/downloads/apps.
  Rec: Send only changed fields; update existing DOM nodes in place. Cache listInstalled() and invalidate on
  install/uninstall. Pause list refresh while user interacts with HUD. Move filesystem scans off UI thread.

[M6] Download progress triggers full chrome and HUD state pushes (PERFORMANCE — see section 6)
  Files: engine/src/cef_client.cpp (OnDownloadUpdated); app/src/browser_window.cpp (onTabDownloadUpdated)
  Detail: OnDownloadUpdated calls onTabDownloadUpdated on every progress update, which calls pushChromeState()
  and (if HUD visible) pushHudState(). pushChromeState rebuilds full tab/vault/download JSON and executes JS;
  pushHudState rebuilds all HUD lists.
  Impact: Large downloads cause many full UI updates/second, high CPU, lost HUD focus. Compounds M5.
  Rec: Throttle/coalesce download updates to ~4Hz or on meaningful percentage changes. Update only affected
  download row. Do not push full chrome state for progress changes.

[M7] Background audio/video tabs still throttled (no audible tracking)
  Files: app/src/browser_window.cpp (reconcileRendererPriorities); policy/src/throttle_planner.cpp
  Detail: reconcileRendererPriorities always passes empty media set. Planner throttles any background tab not
  in active_tabs/media_tabs when on battery. No CEF audible-state integration.
  Rec: Track audible tabs (CEF/Chromium audible state) and feed into media_tabs. If unavailable, be
  conservative and do not throttle background tabs that may be playing media.

[M8] PR_SET_TIMERSLACK is per-thread, not process-wide
  Files: hal/src/power_governor.cpp; app/src/main.cpp; app/src/browser_window.cpp
  Detail: applyTimerSlackNs() calls prctl(PR_SET_TIMERSLACK, ...) affecting only the calling thread. Called
  on main/UI thread and subprocess main thread, not CEF renderer/GPU/IO/worker threads. Initial value
  (1ns turbo) and later policy value (50us AC) inconsistent.
  Rec: Document that timer slack is per-thread; apply in each affected thread via thread-start hook or drop
  the claim. Align initial and steady-state values. Measure actual effect before keeping tuning.

[M9] Refresh-rate control hardcodes 144 Hz, assumes eDP/GNOME, races async applies
  Files: policy/src/power_policy.cpp; hal/src/display_refresh.cpp
  Detail: targetRefreshHz returns 60 on battery/cinema or 144 otherwise. applyEdpRefreshSync only considers
  connectors starting with "eDP" and only talks to org.gnome.Mutter.DisplayConfig. KDE/Sway/X11 users get no
  effect. 120Hz panel on AC stays at 120 (best_dist 24 > 20); 165Hz stays at 165 (21 > 20); only 144Hz is
  reliably switched. setEdpRefreshRateAsync sets last_hz_ before apply completes; failure not retried; rapid
  toggles spawn concurrent threads applying modes out of order.
  Rec: Discover panel supported modes and choose highest rate <= configured cap, or 60 on battery. Serialize
  applies through one worker; update last_hz_ only after success; retry on failure. Support KDE/Sway or make
  explicitly GNOME-only.

[M10] GPU isolation fallback can select dGPU; libva paths Fedora-specific
  Files: hal/src/gpu_isolator.cpp
  Detail: If no AMD/Intel render node found, fallback is /dev/dri/renderD128 or first node (may be NVIDIA).
  applyIsolationEnv only sets LIBVA_DRIVER_NAME=radeonsi when vendor==0x1002. LIBVA_DRIVERS_PATH hardcoded to
  /usr/lib64/dri-freeworld:/usr/lib64/dri (Fedora layout); on Debian/Arch this can prevent libva finding the
  real driver.
  Rec: Return empty/unknown node when no iGPU found. Detect distro libva driver dir or leave unset. Verify
  selected node is intended iGPU before passing render-node-override.

[M11] isOnBatteryBoot over-triggers on battery-less desktops
  File: hal/src/power_governor.cpp
  Detail: Returns true if mains offline even when no Battery supply exists. Desktop with AC unplugged (or no
  UPower battery) treated as battery mode.
  Rec: Require at least one Battery supply whose status is Discharging (or mains offline AND battery present).
  Treat "no battery" as AC/unknown.

[M12] Cookie preference dead code; site-data clearing incomplete
  Files: app/include/explorer/app/prefs_store.hpp; app/src/browser_window.cpp (clear_site_data, clear_all_data)
  Detail: UserPrefs::save_cookies loaded/saved/tested but never used to configure CEF or cookie manager.
  clear_site_data calls DeleteCookies(t->url, "", ...) with full page URL; CEF expects URL to identify
  origin/path, may not delete cookies for all paths. Only clears localStorage/sessionStorage for current
  document; not IndexedDB, CacheStorage, service workers, HSTS.
  Rec: Wire save_cookies to CEF settings/cookie manager (or remove pref). Delete cookies by origin not full
  URL. Use CEF/Chromium APIs to clear cache, storage, service workers, and other site data; document gaps.

[M13] WebApp install reports success when nothing written
  Files: webapp/src/webapp_installer.cpp; app/src/browser_window.cpp (onWebAppInstallFinished)
  Detail: install() creates directories ignoring ec; opens desktop file with ofstream and never checks
  is_open() or write success. Returns populated InstalledWebApp even if desktop file not created. Caller's
  detached thread always passes true to onWebAppInstallFinished, so HUD says "Installed app" even on failure.
  launch() does not wait for child; failed exec leaves zombie.
  Rec: Check directory creation, ofstream state, close/flush errors; return empty result on failure. Pass
  actual success flag to onWebAppInstallFinished. Reap launch child or use posix_spawn + SIGCHLD handler.

[M14] WebApp paths ignore PREFIX/XDG_DATA_HOME; desktop Exec not quoted
  Files: app/src/main.cpp; webapp/src/webapp_installer.cpp
  Detail: main.cpp hardcodes $HOME/.local/bin/explorer, ~/.local/share/applications,
  ~/.local/share/icons/hicolor. install.sh installs to ${PREFIX:-$HOME/.local}/bin/explorer; if PREFIX is
  /usr/local, WebApp desktop entries point at nonexistent binary. XDG_DATA_HOME ignored for WebApps though
  defaultProfileDir() honors it. Exec= writes browser path and URL without quoting; home dir with spaces
  produces broken desktop entry.
  Rec: Pass actual browser binary path and XDG data dirs from main/installer config. Quote/escape Exec args
  per Desktop Entry spec. Add test with path containing spaces.

[M15] Trusted chrome/HUD bridge tied to browser ID, not URL or navigation state
  Files: app/src/main.cpp (OnBrowserCreated, OnContextCreated); app/src/browser_window.cpp; chrome_bridge.hpp
  Detail: OnBrowserCreated inserts browser ID into trusted_chrome_ids_ when extra_info says is_explorer_chrome.
  OnContextCreated exposes window.explorerHost.post() to any main frame of that browser without checking frame
  URL. Chrome/HUD views loaded from data: URLs but no OnBeforeBrowse guard prevents them navigating elsewhere
  (drag/drop, link, renderer compromise, future UI change).
  Rec: In OnContextCreated, require main frame URL to match expected data: URL/scheme (or per-browser nonce)
  before exposing explorerHost. Implement OnBeforeBrowse for chrome/HUD clients to block non-internal
  navigations. Add command allowlist in browser process. Keep trusted/untrusted renderer processes separate.

[M16] Login capture has no gesture requirement; uses loose prefix check
  Files: app/src/main.cpp (ContentPageBridgeHandler); app/src/browser_window.cpp (onTabLoginSubmitted)
  Detail: Any HTTPS page can call window.__expLoginCapture(user, pass); bridge accepts if frame URL starts
  with https:// (or loose localhost prefix). Injected submit listener does not require user gesture or verify
  form is a login form. pending_login_ stores plaintext password until user accepts/dismisses; not cleansed on
  destruction or navigation.
  Rec: Require recent user gesture and trusted form-submit event; validate form action/origin. Clear
  pending_login_ on navigation, tab switch, window close; cleanse password buffer. Use strict origin parser
  from M2.

[M17] Hand-rolled JSON parsing/escaping incomplete
  Files: app/src/browser_window.cpp (extractJsonField, jsonEscape); app/src/session_store.cpp (escapeJson,
         load); app/include/explorer/app/prefs_store.hpp (load)
  Detail: extractJsonField handles \n \r \t \" \\ but not \uXXXX. jsonEscape does not escape U+2028/U+2029
  (valid JSON but terminate JS string literals in older engines). session_store escapeJson does not escape
  most control chars < 0x20 other than \n/\r; load does not decode \uXXXX. PrefsStore::load uses substring
  matching (line.find("true")) instead of parsing field values.
  Rec: Use a small JSON library (nlohmann/json, RapidJSON, or simdjson) for HUD commands and persistence. If
  hand-rolled retained, implement full JSON string grammar and add round-trip tests. Validate schemas.

[M18] EXPLORER_DISABLE_TUNING=1 also disables the adblock shield
  Files: app/src/main.cpp; engine/src/cef_flags.cpp
  Detail: Shield only constructed when !hw.tuning_disabled. applyHardwareEngineFlags returns early when tuning
  disabled, before adding feature flags. README describes the env var as hardware/power/VA-API/V8 escape
  hatch, not a privacy/security switch.
  Rec: Always construct shield (and vault/webapp services); gate only hardware-specific tuning. If a full
  "vanilla" mode is desired, add separate EXPLORER_DISABLE_SHIELD and document it.

[M19] Build/install hardening missing
  Files: CMakeLists.txt; install.sh; install-cef.sh; update.sh
  Detail: -O3 -march=native on all modules; binary not portable across CPUs (SIGILL on older machines). No
  -fstack-protector-strong, -D_FORTIFY_SOURCE=2, PIE/-fPIE, RELRO, or -Werror. install.sh builds Release and
  runs vacuous Release tests (H1). Does not set/verify chrome-sandbox permissions or explain userns fallback.
  Rec: Use portable baseline (-march=x86-64-v3 or runtime dispatch) for distributed binaries; keep
  -march=native only for local experiments. Add standard hardening flags and -Werror in CI. Run Debug/ASan/
  UBSan tests in CI. Verify/set sandbox helper and document requirement. Add checksum/signature verification
  to installers.

[M20] Missing CEF handlers leave permission/dialog/auth/external-protocol behavior undefined
  Files: engine/include/explorer/engine/cef_client.hpp; engine/src/cef_client.cpp
  Detail: Client implements LifeSpan, Display, Load, Request/ResourceRequest, Download, Keyboard handlers only.
  No CefPermissionHandler, CefJSDialogHandler, CefDialogHandler, CefContextMenuHandler, CefFindHandler,
  CefPrintHandler, CefAudioHandler, or CefRequestHandler::OnBeforeBrowse/OnCertificateError/GetAuthCredentials/
  OnProtocolExecution. Geolocation/notifications/camera/mic, alert/confirm/prompt, HTTP auth, certificate
  errors, mailto:/tel: links rely on CEF defaults (often deny/suppress).
  Rec: Implement explicit permission prompts (or document all permissions denied). Implement JS dialog
  handling. Handle HTTP auth and certificate errors. Decide external-protocol behavior and implement
  OnProtocolExecution. Add UI/tests for these flows.

[M21] GPC/DNT headers not applied to top-level navigation
  File: engine/src/cef_client.cpp (GetResourceRequestHandler)
  Detail: GetResourceRequestHandler() returns nullptr when is_navigation is true, so OnBeforeResourceLoad()
  not called for main document. GPC/DNT header code runs only for subresources.
  Rec: Return this for navigation requests but skip shield evaluation for MainFrame, so header code runs.
  Or set headers via request context / OnBeforeBrowse equivalent. Test main document request headers.

[M22] Favicons loaded by chrome renderer bypass shield
  Files: app/include/explorer/app/chrome_ui.hpp (CSP); app/src/browser_window.cpp (__updateChrome)
  Detail: Top chrome CSP allows img-src https: http: data:. __updateChrome sets img.src = t.favicon for tab
  icon. Chrome view has no ExplorerCefClient/shield; request made by privileged chrome renderer.
  Rec: Fetch favicons through content tab's network stack/shield, or only allow data: icons. Restrict img-src
  to data: and proxy approved favicons. Validate favicon URL scheme and size.

[M23] Session/prefs persistence not durable; prefs world-readable
  Files: app/src/session_store.cpp (saveAtomic); app/include/explorer/app/prefs_store.hpp (save)
  Detail: SessionStore::saveAtomic writes temp, chmod 0600, renames, chmod 0600 — but does NOT fsync file or
  directory. PrefsStore::save writes temp with default permissions (0644), renames without chmod/fsync. Both
  ignore write/rename errors.
  Rec: Create temp files with 0600, fsync file and parent directory, then rename. Check and report errors.
  Use same atomic-write helper for session and prefs.

[M24] resolveDownloadPath can overwrite after 999 collisions
  File: engine/src/cef_client.cpp
  Detail: Loop tries stem(1..999); if all exist, returns original candidate path which already exists.
  Rec: Add random/unique suffix or fail download with error. Use O_EXCL when creating destination if CEF
  allows.

[M25] --app= and omnibar scheme handling broader than web-content navigation policy
  Files: policy/src/navigation_policy.cpp; app/src/main.cpp; app/src/browser_window.cpp
  Detail: normalizeOmnibarInput allows file://, chrome://, data:, explorer://, about:. --app= accepts any
  string; --app=file:///etc/passwd accepted. Web-content popups filtered to http/https, but no OnBeforeBrowse
  policy for in-page navigation.
  Rec: Keep file:// for explicit omnibar input, but add OnBeforeBrowse allowlist for web-initiated
  navigation. Validate --app= to http/https (or documented set). Log/confirm local-file navigation.

[M26] Error handling inconsistent and often silent
  Files: webapp/src/webapp_installer.cpp; app/src/session_store.cpp; app/include/explorer/app/prefs_store.hpp;
         vault/src/password_vault.cpp; hal/src/display_refresh.cpp; hal/src/power_governor.cpp
  Detail: Many std::error_code results ignored (create_directories, rename, file_size). webapp install ignores
  ofstream failure. ensureKey silently rekeys on corruption. Several sd_bus_* return values unchecked.
  spawnDetachedXdgOpen/launch do not report exec failure.
  Rec: Adopt consistent error-handling policy: return/propagate errors, log at call site, surface user-visible
  failures for install/save/update. Add negative tests for unwritable paths and failed helper processes.

4. LOW-SEVERITY / INEFFICIENCY FINDINGS
================================================================================

[L1] Rule count is line count, not compiled-rule count
  shield-brave/src/lib.rs counts non-empty/non-comment lines, not rules adblock-rust actually compiled. HUD
  "N rules" approximate.
[L2] Invalid UTF-8 and lock poisoning fail open in Rust shield
  from_utf8(...).unwrap_or("") turns invalid URL into empty string; Request::new fails and returns 0 (allow).
  If panic poisons RwLock, evaluate returns 0 (allow).
[L3] Filter update concurrency not serialized
  Two update clicks write same *.tmp files and call reload concurrently; loadCombinedRules() can read partially
  written file. Add mutex/in-flight flag and atomic staging directory.
[L4] Blocked count never reset; not tied to ruleset
  HUD count accumulates for process lifetime, including across filter reloads. Label "since launch" or reset on
  reload.
[L5] std::hash app IDs not stable; truncate to 32 bits
  Different libstdc++ versions may produce different hashes; 32-bit truncation can collide. Use stable hash
  (SHA-256 prefix) and handle collisions.
[L6] WebApp desktop files store full URL incl. query tokens, world-readable
  Installing app on URL with OAuth/session query params writes them to 0644 .desktop file and Exec line.
[L7] uninstall.sh --purge-data leaves WebApp desktop entries/icons
  Removes main browser files but not ~/.local/share/applications/explorer-app-*.desktop or icons.
[L8] open_browser_count_ is dead state
  Incremented/decremented but never read for shutdown decisions; checkFinishShutdown uses tabs_/retiring_tabs_.
[L9] onTabFaviconChanged only updates chrome when >1 tab
  With single tab the tab bar is hidden; favicon state stale if second tab opened later.
[L10] pending_login_ plaintext in memory, not cleansed
  Clear on navigation/tab switch/close; cleanse password buffer. Consider secure_string.
[L11] resolveDownloadPath trusts XDG_DOWNLOAD_DIR and existing symlinks
  Path checked with exists() then handed to CEF; local attacker who can create symlink at destination could
  redirect write. Use O_NOFOLLOW/O_EXCL where possible.
[L12] Downloads list capped at 30 entries
  Older completed downloads disappear from HUD and cannot be opened via dl_open. Use persistent download
  history or larger cap.
[L13] clear_site_data does not clear cache/service workers/IndexedDB
  See M12. Functional/privacy gap rather than code defect.
[L14] EXPLORER_DISABLE_TUNING still samples telemetry
  services.telemetry created regardless of tuning; onTelemetryTick still reads sysfs. If escape hatch meant to
  disable hardware access, gate telemetry too.
[L15] readablePath() opens every candidate file during telemetry construction
  One-time cost but can touch many hwmon/power_supply files. Consider lazy detection or caching.
[L16] sampleLite() is not the "2-file" sample described by comment
  sampleLite() also reads every fan input and battery power. Update comment or reduce work.
[L17] RAPL counter wrap/resume can produce huge wattage spike
  prev_rapl_ not reset after suspend/resume or counter wrap; *energy >= prev_rapl only guards one direction.
  Clamp/ignore implausible deltas.
[L18] MutterDisplayRefreshCtrl parsing ignores some sd_bus_message_read failures
  Logical-monitor read result unchecked; malformed replies can desynchronize message cursor. Check every
  read/skip return.
[L19] install.sh deletes /tmp/explorer_* broadly
  rm -rf /tmp/explorer_v2_* etc. can remove another user's files. Use private temp dir.
[L20] install.sh/update.sh/uninstall.sh pkill -f patterns broad
  A process whose command line contains explorer-cef/Release/explorer can be killed. Prefer PID files or exact
  executable matching.
[L21] README claims exceed implementation
  "atomic session restore" undermined by H4; "Widevine" not registered (H10); "rock-solid multi-tab stability"
  undermined by H4/H5; "zero Chrome bloat" is marketing, not measurable.

5. PERFORMANCE ANALYSIS AND IMPROVEMENT AREAS
================================================================================

This section is the focus of your request: where to improve performance. Below are the confirmed
inefficiencies, ranked by impact.

[P1] HUD rebuilds ALL DOM lists every 2 seconds on the UI thread — BIGGEST UI JANK SOURCE
  Files: app/src/browser_window.cpp (pushHudState, lines 756-842; onTelemetryTick, lines 1461-1479);
         app/include/explorer/app/chrome_ui.hpp (__updateHud)
  Current behavior:
    - onTelemetryTick fires every 2000ms (5000ms on battery, HUD closed).
    - When HUD visible, pushHudState(serializes) is called EVERY tick.
    - pushHudState calls services_.vault->listAll() (returns full vector by value), iterates downloads_,
      calls services_.webapp_installer->listInstalled() which scans ~/.local/share/applications and reads
      EVERY .desktop file from disk, then builds one giant JSON string and ExecuteJavaScript()s it.
    - __updateHud in the HUD page clears innerHTML for vault/download/app lists and recreates every DOM node
      on each update (lines ~746, ~780, ~811 of chrome_ui.hpp).
  Impact: Focus and scroll position lost every 2s. GC churn + disk I/O on the UI thread cause visible jank,
  especially with many credentials/downloads/apps. The UI thread is blocked on filesystem reads during every
  telemetry tick.
  Fix:
    - Send only changed fields (diff-based update). Compare against previous snapshot; push only deltas.
    - Update existing DOM nodes in place instead of clear+recreate.
    - Cache listInstalled() results; invalidate only on install/uninstall.
    - Pause list refresh while user is interacting with the HUD; refresh only when the corresponding tab is
      opened.
    - Move filesystem scans (listInstalled) off the UI thread (post to a background thread, post result back).
    - Consider throttling pushHudState to ~1Hz when HUD is open and idle.

[P2] Download progress triggers FULL chrome + HUD state push on every progress event
  Files: engine/src/cef_client.cpp (OnDownloadUpdated, lines 301-329);
         app/src/browser_window.cpp (onTabDownloadUpdated, lines 1218-1234)
  Current behavior:
    - OnDownloadUpdated is called by CEF on every download progress update (potentially many times per
      second for large downloads).
    - onTabDownloadUpdated calls pushChromeState() (rebuilds full tab/vault/download JSON, ExecuteJavaScript)
      AND, if HUD visible, pushHudState() (rebuilds ALL HUD lists, including filesystem scan for webapps).
  Impact: Large downloads cause many full UI updates per second, high CPU, lost HUD focus. Compounds P1.
  Fix:
    - Throttle/coalesce download updates to ~4 Hz or only on meaningful percentage changes (e.g. >=1% delta).
    - Update only the affected download row (send download id + percent, not full list).
    - Do not push full chrome state for download progress changes; push only download-specific data.

[P3] Telemetry sampling does filesystem I/O on the UI thread every tick
  Files: hal/src/telemetry.cpp (sample, sampleLite); app/src/browser_window.cpp (onTelemetryTick)
  Current behavior:
    - sample() reads: AC online, battery status/power/voltage/current, CPU temp, iGPU temp/freq/power/busy,
      EVERY fan input (up to 4), RAPL energy, /proc/stat (CPU percent), dGPU runtime status — all via
      std::ifstream open/read/close, on the UI thread.
    - sampleLite() (claimed "2-file sample") actually reads AC, battery status/power, AND every fan input.
    - onTelemetryTick calls sample() or sampleLite() synchronously on the UI thread every 2s (5s battery).
  Impact: UI thread blocked on sysfs reads every 2 seconds. Contributes to jank, especially on systems with
  many hwmon/fan inputs or slow storage.
  Fix:
    - Move telemetry sampling to a background thread; post the snapshot back to the UI thread.
    - Cache sysfs file descriptors (open once, pread repeatedly) instead of open/read/close every tick.
    - Reduce sampleLite() to truly minimal reads (AC + battery status only when on battery).
    - Increase the tick interval when nothing is changing (adaptive polling).

[P4] findTab() is an O(n) linear scan called on virtually every tab operation
  File: app/include/explorer/app/browser_window.hpp (findTab, line 1509)
  Current behavior:
    - findTab() iterates the entire tabs_ vector to find a tab by ID.
    - Called from activeTabEntry(), onTabAddressChanged, onTabTitleChanged, onTabFaviconChanged,
      onTabProgressChanged, onTabLoadingChanged, onTabRendererPid, onTabDoClose, onTabClosed,
      onTabScrollRevealTopBar, onTabLoginSubmitted, pushChromeState (indirectly), etc.
  Impact: O(n) per tab event. With many open tabs, every address/title/progress/loading change does a linear
  scan. Minor individually but cumulative.
  Fix:
    - Maintain a std::unordered_map<uint64_t, TabEntry*> or index alongside tabs_ for O(1) lookup by ID.
    - Keep it synchronized on insert/erase.

[P5] pushChromeState builds a complete JSON string and ExecuteJavaScripts it on every change
  File: app/src/browser_window.cpp (pushChromeState, lines 667-722)
  Current behavior:
    - Called from onTabAddressChanged, onTabTitleChanged, onTabLoadingChanged, activateTab, closeTab,
      toggle_adblock, etc. — many call sites.
    - Each call builds a full JSON string (tabs array, URL, progress, adblock, blocked count, site creds,
      battery pill, etc.) and ExecuteJavaScripts it.
  Impact: Repeated full-state serialization and JS execution for incremental changes (e.g. just a title
  change). Wasted CPU and IPC.
  Fix:
    - Adopt a diff-based model: push only fields that changed since last push.
    - Separate high-frequency fields (progress, loading) from low-frequency fields (tabs list, title).
    - Throttle progressive updates (progress) separately from state changes.

[P6] resolveDownloadPath loops up to 999 exists() checks on collision
  File: engine/src/cef_client.cpp (resolveDownloadPath, lines 29-68)
  Current behavior:
    - On collision, checks exists() for stem(1)..(999). In the worst case (999 existing files), that's 999
      filesystem stat calls before giving up and returning the colliding path (overwrite!).
  Impact: Latency spike on download start in collision-heavy Downloads folders. Also a correctness bug (L12,
  M24) — can overwrite existing files.
  Fix:
    - Append a random/unique suffix (e.g. timestamp or UUID fragment) instead of linear scan.
    - Or use O_EXCL when creating the destination.
    - Cap the scan at a small number (e.g. 10) then fall back to a unique suffix.

[P7] -march=native makes binary non-portable; no hardening flags
  File: CMakeLists.txt (line 26)
  Current behavior:
    - All modules compiled with -O3 -march=native. Binary optimized for the build host CPU and can crash
      with SIGILL on older/different machines. Not suitable for distribution.
  Impact: Non-portable builds; reduced exploit mitigations (no stack protector, no FORTIFY, no PIE/RELRO).
  Fix:
    - Use portable baseline (-march=x86-64-v2 or x86-64-v3) for distributed binaries; keep -march=native only
      for local experiments (behind a flag).
    - Add -fstack-protector-strong, -D_FORTIFY_SOURCE=2, -fPIE/-pie, -Wl,-z,relro,-z,now, -Werror.

[P8] Vault listAll() returns full entries vector by value on every HUD update
  File: vault/src/password_vault.cpp (listAll, line 308); app/src/browser_window.cpp (pushHudState, line 812)
  Current behavior:
    - pushHudState calls services_.vault->listAll() every 2s, which copies the entire entries_ vector (with
      all credentials) just to serialize origin+username to JSON.
  Impact: Unnecessary copying of all credentials on every telemetry tick.
  Fix:
    - Add a method that returns only (origin, username) pairs, or a const reference to entries_ for read-only
      iteration. Avoid copying passwords into the HUD JSON (already avoided, but the vector copy remains).

[P9] CefPostDelayedTask(rescheduled every telemetry tick) even when nothing changed
  File: app/src/browser_window.cpp (onTelemetryTick, line 1478)
  Current behavior:
    - onTelemetryTick unconditionally reposts itself with CefPostDelayedTask every tick (2s/5s), even when
      telemetry values haven't changed and HUD is closed.
  Impact: Wakes the UI thread periodically with no useful work.
  Fix:
    - Only repost if state changed or HUD is visible. Use last_telemetry_sig_ pattern (already used for
      pushChromeTelemetry) to skip redundant work.

[P10] open_browser_count_ is dead state (wasted writes)
  File: app/include/explorer/app/browser_window.hpp (line 182); app/src/browser_window.cpp (lines 1114-1123,
        1125-1128, 1390)
  Current behavior:
    - Incremented/decremented in onChromeBrowserCreated, onChromeBrowserClosed, onTabCreated, onTabClosed but
      NEVER read for any decision. checkFinishShutdown uses tabs_/retiring_tabs_ instead.
  Impact: Negligible CPU but dead code; adds confusion and maintenance noise.
  Fix: Remove open_browser_count_ entirely or use it consistently for shutdown decisions.

[P11] WebApp listInstalled() parses every .desktop file line-by-line on every HUD update
  File: webapp/src/webapp_installer.cpp (listInstalled, lines 177-202); called from pushHudState (line 832)
  Current behavior:
    - directory_iterator over apps_dir_, then for each .desktop file: open, getline loop parsing Name/Icon/
      X-Explorer-WebApp-URL. Runs on the UI thread every 2s when HUD visible.
  Impact: Disk I/O + string parsing on UI thread every telemetry tick. Grows with number of installed
  webapps.
  Fix: Cache the list; invalidate only on install/uninstall. Move to background thread.

[P12] Session save debounced at 600ms but flushSessionNow() called from multiple close paths
  File: app/src/browser_window.cpp (scheduleSessionSave, onDebouncedSessionSave, flushSessionNow)
  Current behavior:
    - scheduleSessionSave uses a 600ms debounce (good), but handleCanClose() and handleWindowDestroyed() both
      call flushSessionNow() synchronously, potentially writing multiple times during close.
  Impact: Redundant disk writes during shutdown; combined with H4 (session overwrite bug).
  Fix: Single snapshot save at start of close (see H4); remove redundant flushSessionNow() from
  handleWindowDestroyed.

6. KEY DESIGN ISSUES
================================================================================

[D1] Lifetime/ownership of async work is not modeled
  Detached std::thread, raw `this`, base::Unretained, fork, and CefPostTask without a shared lifetime /
  cancellation abstraction. Root cause of H1/H5/H6/H8. A small TaskRunner/executor owned by RuntimeServices,
  with weak_ptr tokens and join-on-shutdown, would remove a whole class of bugs.

[D2] The close state machine is implicit
  closing_, retiring_tabs_, open_browser_count_, DoClose, CanClose, OnBeforeClose interact without an
  explicit state enum or timeout. H3/H4 are symptoms. Model the window lifecycle as an explicit state machine
  (Open -> ClosingTabs -> ClosingWindow -> Destroyed) with cancellation and a timeout.

[D3] Service graph is null-heavy in subprocesses
  RuntimeServices holds shared_ptr for every service; subprocesses leave most null and call sites scatter null
  checks. Prefer std::optional or a variant keyed by process role.

[D4] Throttle planner lacks media awareness (H3/M7)
  No CEF audio callback integration; background media tabs get throttled.

[D5] Hardware assumptions baked in
  144 Hz, eDP/GNOME, Fedora libva paths, Ryzen 7 5800H V8 flags, -march=native, AMD-only telemetry make the
  browser fragile on other hardware. EXPLORER_DISABLE_TUNING is the only escape; default path should degrade
  gracefully rather than assume Cezanne.

[D6] Persistence is ad-hoc and duplicated
  Session, prefs, vault, webapp metadata each use hand-rolled formats and error handling. A shared atomic-write
  + JSON/schema layer would fix M17/M23 and enable migrations.

[D7] No integration test coverage
  Only pure-logic modules are tested. BrowserWindow, CEF wiring, vault autofill flow, shield reload untested.
  Regressions caught only at runtime.

[D8] Security trust boundary identified by browser ID, not URL/context (M15)
  Privileged capability granted to a browser/view and trusted for its lifetime. Prefer a capability token
  bound to the exact frame URL/context, with a navigation guard and command allowlist.

[D9] UI update strategy is "rebuild everything" (P1/P2/P5)
  HUD/chrome state pushes serialize and rebuild full lists on a timer and on every download progress event. A
  diff-based update model (or a small reactive store) would improve responsiveness and reduce IPC.

[D10] Error handling not part of the design (M26)
  Many operations fail silently. Install/update/save/clear operations need explicit user-visible outcomes and
  logs.
